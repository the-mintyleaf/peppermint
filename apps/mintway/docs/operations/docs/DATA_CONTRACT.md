# Data Contract — Platform Operations

**Owner app:** `operations`
**Version:** 1.0.0
**Status:** Active
**Created:** 2026-07-15
**Purpose:** Owns operational/maintenance capabilities for the platform. The first is the on-demand
database backup: a `DatabaseBackup` audit record for each `pg_dump` archive written to disk. This app
does NOT own authentication (`authenticate`), applicant data (`applicant`), or the access-control
metadata registry (`core.policy_engine`); it references `authenticate.User` only as the actor FK.

## 1. DatabaseBackup

**Purpose:** Immutable audit record of a single on-demand PostgreSQL backup and its provenance. The
dump archive itself lives on disk under `settings.DB_BACKUP_ROOT`; this row stores only its `filename`
(the absolute path is always re-derived server-side — never stored or accepted from a client, §14).
**Table:** `operations_databasebackup`
**`status` choices:** `in_progress`, `completed`, `failed`

| Field           | Type                 | Required | Nullable   | Generated | Description                                                               |
| --------------- | -------------------- | -------- | ---------- | --------- | ------------------------------------------------------------------------- |
| id              | UUID                 | —        | No         | Yes       | Primary key (public identifier)                                           |
| filename        | CharField(128)       | Yes      | No         | Yes       | `backup_<YYYYMMDD_HHMMSS>.dump` (UTC, sortable, unique). ASCII system id. |
| database_name   | CharField(128)       | Yes      | No         | Yes       | Name of the database that was dumped                                      |
| dump_format     | CharField(16)        | Yes      | No         | Yes       | Always `custom` (pg_dump `-Fc` archive)                                   |
| status          | CharField(20)        | Yes      | No         | Yes       | Lifecycle state (see choices); default `in_progress`                      |
| size_bytes      | BigInteger           | No       | Yes        | Yes       | Archive size; set on completion                                           |
| checksum_sha256 | CharField(64)        | No       | No (blank) | Yes       | SHA-256 of the archive; set on completion (§14)                           |
| reason          | TextField            | No       | No (blank) | No        | Optional operator note; Unicode-normalized (§39.2)                        |
| error_message   | TextField            | No       | No (blank) | Yes       | Failure description (credential-free); set on failure                     |
| created_by      | FK→authenticate.User | Yes      | No         | No        | Superadmin who triggered the backup (PROTECT)                             |
| created_at      | DateTime             | —        | No         | Yes       | Creation timestamp (system-internal — **no BS representation**, §39.4)    |

**Validation Rules:**

- `filename` is generated by the service, never client-supplied; unique.
- `reason` is passed through `core.nepal.text.normalize_unicode` on write (§39.2).
- `status` transitions one way: `in_progress` → `completed` or `in_progress` → `failed`.

**Indexes:** `status` (`db_index=True`) — filtered when surfacing failed/in-progress backups; `filename` unique index.

**Soft Delete:** N/A — records are immutable audit rows; they are never soft- or hard-deleted by the
app. File retention/rotation is out of scope for this version (see `API.md` limitations).

**Bilingual identity (§39.1):** N/A — `filename` is an ASCII system identifier, not a human-facing
entity name, so the `_np`/`_en`/`_romanized` pattern does not apply. No user-facing name/title field exists.

**Example:**

```json
{
  "id": "5fefc7dd-9f6a-4c06-a9d8-66decb9f2565",
  "filename": "backup_20260715_155501.dump",
  "database_name": "mintway_prod",
  "dump_format": "custom",
  "status": "completed",
  "size_bytes": 4194304,
  "checksum_sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "reason": "pre-migration snapshot",
  "error_message": "",
  "created_by": "superadmin",
  "created_at": "2026-07-15T10:10:10Z"
}
```

**Cross-App Dependencies:** `authenticate.User` — `created_by` FK (actor). No reverse coupling.
**Security Notes:** The backup file contains ALL database contents (password hashes, PII). See `SECURITY.md`.
